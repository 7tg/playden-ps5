# Complete pending file effects

`ApplyPendingPublicationFiles` replaces the coordinator tests' fixture file writes with the production apply adapter. It checks frozen canonical paths, requires the exact pending operation through the registry/DXVK adapters, holds the caller's borrowed stable publisher descriptor, and publishes profiles, every required input preset, the one-entry catalog, canonical descriptor and schema-2 completion metadata. The coordinator still independently runs shared native complete-set verification before committing the receipt.

The adapter creates private profiles/input children only inside the already owned private library after pending admission, with child and parent fsync barriers. It requires the staged title and game working directories to already exist. It never allocates/restages a bottle or title. Each target admits absent initial state, retained prior metadata hashes, or already intended exact bytes in mode 0600; missing prior owned files and unknown changed bytes are collisions. Initial ownership/absence must first be established by the production producer's mandatory read-only preflight; matching intended bytes during pending recovery do not independently grant initial ownership.

Each file uses an exclusive temporary, file fsync, checked rename, parent fsync and exact durable readback. Failed temporaries remain for reconciliation; no blanket cleanup or immediate rollback occurs. Existing unused prior profile/input files are preserved; the exact new catalog and required preset list determine the admitted launch set. Registry and DXVK effects use their already qualified pending adapters. This is an individually durable receipt protocol, not a cross-directory atomic rename.

The original link failed on the missing complete-writer entry point. With implementation, coordinator tests now use the production complete writer. Host fork/exit tests interrupt after the two directory boundaries and each of five fixture file boundaries, then recover in another process while preserving a game save sentinel. An actual RLIMIT_FSIZE failure during the first profile write leaves the target absent and the pending operation recoverable. Tests also refuse a foreign catalog introduced into pending state, publish changed input/descriptor/metadata from an actual verified prior set, and refuse a missing prior owned profile. The update fixture explicitly retires the earlier journal under its test lease; it does not prove or implement production journal retirement.

All 105 host tests, warning/diff checks and SDK v0.43 settings-publication archive compilation pass. Production preflight/OWNER/registration adapters, next-operation journal retirement, installer/UI integration, final application link, independent Task C review and PS5 failure/retry acceptance remain open. No console application or Wine runtime was replaced.
