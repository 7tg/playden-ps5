# Durable prepared intent handoff

Prepared operations now persist exclusively as private `settings-intent-<UUID>.v1` files before Prepare succeeds. They use the same bounded PWOP2 codec, real referenced-backup validation, durable exclusive storage and exact readback as active journals. Recovery additionally requires canonical nonnil lowercase UUID names and exact filename-to-transaction binding. Existing names are never overwritten/adopted by creation. Prepared intent alone grants neither file-effect ownership nor readiness.

OWNER Prepare loads both the active journal and requested prepared intent under its existing publisher lease. Corruption/unavailability or disagreement refuses recovery. A matching prepared intent retains the original complete snapshot, plan digest and timestamp; changed plans/kit/OWNER intent refuse. A different blocked OWNER operation or unfinished previous active operation remains blocked. Once a new capture passes full preflight, it durably stores the intent and rechecks lease/activity before returning. The active journal/receipt protocol and OWNER blocking still gate all live effects.

This preserves capture across process exit before active journal creation and across retirement of an earlier completed journal before new OWNER blocking. The requested transaction ID must still come from the caller; startup job identity discovery/routing is unfinished. A backup orphan left before a valid prepared intent exists remains unbound evidence and is not adopted. Prepared intents, archives and backups are retained; no cleanup policy is introduced. Initial control setup and explicit uncertain-registration recovery are separate open work.

Host tests terminate a producer after successful capture but before any publication, recreate the repository and OWNER callbacks, and recover original registry/DXVK bytes and timestamp despite a later supplied clock value. The same bound immutable backup is recovered through the valid intent; matching orphan bytes alone do not authorize capture. Tests also recover the next operation after previous-journal archival, refuse changed same-transaction plans, and cover exclusive collisions, corruption, permissions, hardlinks, symlinks, nil/unsafe names and mismatched transaction filenames. An actual RLIMIT_FSIZE intent write failure leaves only retained temporary evidence and no valid intent. Missing operation/intent reads now sync absence before returning absent.

All 105 host tests, warning/diff checks and SDK v0.43 archive compilation pass. Startup intent identity/routing, control initialization, orphan intent recovery without a valid prepared journal, installer/UI integration, final application link, independent Task C review and actual PS5 acceptance remain unfinished. No console application or Wine runtime was changed.
