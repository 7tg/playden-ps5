# Durable OWNER and registration callbacks

`SettingsPublicationOwner` supplies the coordinator's production callbacks using InstallRecordStore, PackageInstaller and NativeCoordinator. It requires the existing reserved record's immutable identities, original launch fields and exact artifact bindings to match the frozen operation, allows only previous/desired revisions, refuses removing/conflicting operations and unknown/active activity, and verifies staged immutable title/template/bottle/artifact ownership via package inspection before durably blocking readiness. It never stages, allocates, copies or publishes through PackageInstaller mutation methods.

OWNER persistence records the publication UUID and phase. Already armed registration/await-native steps survive retry instead of being reset to a fresh submit step. Reconciliation runs only after the coordinator verifies the exact committed complete set under its publisher lease; legacy profile-only package status cannot authorize Ready. It rechecks immutable ownership and positively stopped activity, requires coherent native inventory/source ownership, and durably arms initial registration before submission. Accepted/queued submission persists await-native before final Ready. Observed background scan also persists await-native. Armed/uncertain requests are queried without automatic resubmission. Settings updates require the existing owned registration and never register a replacement. Ready persistence records the exact desired revision and clears the journal/failure; failure retains the committed files and prior durable OWNER phase.

Tests use the real RuntimeInstallRepository and RepositoryInstallRecordStore with private durable files, actual publication/preflight/verifier adapters, and controlled package/native collaborators. They recreate OWNER callbacks from a freshly loaded repository after a refused Ready write and a queued registration. Retry does not apply files or submit registration again. A next-operation update fixture refuses missing existing native registration and completes after it becomes visible, without another registration or file application. Test-only journal retirement seeds that update; production retirement remains unfinished. Negative cases cover record launch drift, invalid immutable artifacts, unknown activity, failed registration with retained arm, and background scan with no submit. All PackageInstaller mutation counts remain zero.
