# Service routing and frozen OWNER recovery

RuntimeInstallService accepts a complete publication driver. It routes initial `prepare/publish-profile` through that driver before legacy profile-status shortcuts, and always routes `settings-control`/`settings-publication` journals through the complete driver. Missing drivers refuse managed journals without falling into legacy registration. The driver owns persistence; the service never advances, fails or overwrites its pre-callback OWNER copy after execution. Complete results require matching durable Ready readback, cleared journal/failure and nondecreasing revision. Registration-pending results retain registering OWNER and report the pending error category. Cancellation and active/unknown activity refuse managed work without altering recovery evidence.

Managed Retry preserves UUID, operation and registration arm, including `register`/`await-native`; it never changes them to the legacy `query-native` resubmission step. It does not discard frozen recovery authority because a newer recipe is unavailable. The complete driver must still perform its own provenance, lock, frozen-byte, receipt and native admission gates.

SettingsPublicationOwner::Resume discovers the operation using the persisted managed OWNER UUID. It resumes matching control setup, acquires the publisher lease, loads active/prepared journals with real bounded codec/backup policy, rejects corruption/mismatches/foreign transactions, validates OWNER/revision/activity and then releases its inspection lease. The existing complete coordinator reacquires and independently checks the stable lock, journal, receipt and immutable ownership before effects. Resume derives canonical publication paths and uses the production callbacks, including real file effects, shared native semantic verification and durable OWNER/native reconciliation. It does not regenerate settings or recipes. An active journal may recover without an optional prepared copy; disagreement when both exist refuses. Missing frozen intent leaves setup explicitly unfinished.

Unit service tests cover callback ownership of latest records, routing before profile shortcuts, missing driver, registration arms preserved on retry, pending categorization, dishonest Complete before Ready, cancellation and activity refusal. An integration fixture uses the real durable repository, production OWNER, producer, coordinator, file effects and shared native verifier, with controlled package/native collaborators. It reopens the repository after initial capture, discovers its frozen operation through OWNER, waits for queued registration without resubmission, reconciles Ready, then recovers a pending next-revision update without replacement registration. Corrupt/missing/wrong-UUID intent tests retain evidence and make no profile/registration effects. Routing and Resume were observed RED before implementation.

All 105 host tests pass; actual SDK v0.43 service/publication archives compile. This is not final native application linkage, PS5 acceptance, Wine lifetime or gameplay evidence. The optional legacy adapter remains for existing callers; FilesystemPackageInstaller still needs its schema-1 inspector/publisher replaced by complete schema-2 receipt verification and publication directory creation moved behind pending. Application/installer wiring remains open. Startup capture discovery is implemented for persisted managed UUIDs only: a prepared update while OWNER is still Ready and pre-capture setup without frozen intent need job identity/planner routing. Explicit uncertain-registration recovery, final independent review and console gates remain unfinished. No console build or runtime changed; PS5 is released.
