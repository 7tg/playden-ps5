# Private control initialization

SettingsPublicationOwner now creates the initial `.playden-control` directory (0700) and stable empty `publication.lock` (0600, current EUID, one link) inside an already staged, independently owned private bottle data root. It validates immutable reserved OWNER/package provenance and positively stopped native activity. It requires initial control-path absence, syncs that observation, then durably persists a transaction-specific `settings-control/initialize-control` OWNER intent before creating anything. Directory, parent, lock file and parent durability are individually checked. A real exclusive lease and renewed OWNER/activity/provenance checks precede durable `control-ready` completion. Setup never grants Ready, registers a title, stages game/title/bottle data or publishes settings.

Matching interrupted intent can resume with the same canonical nonnil lowercase UUID. Retries never truncate, rename or replace an existing lock; malformed/nonempty/wrong-mode/wrong-owner/hardlinked/symlink locks are refused. A completed setup refuses missing directories/locks rather than silently recreating a different lease inode. Busy readers prevent setup completion/capture. Initial paths without a durable setup intent are refused even when their mode/content appears suitable. As with ManagedDirectory, this assumes approved coordinated namespace writers; it does not prove ownership against hostile concurrent path replacement. The OWNER journal stores creation intent, not a persistent inode inventory.

Prepare invokes this setup for a missing initial control path and resumes matching setup journals before acquiring its capture lease. It refuses preexisting initial control paths lacking creation/publication intent; durable Ready updates still use the complete prior publication verifier. Test fixtures that manually established control paths now explicitly record their fixture authorization, while fresh setup tests use the production initializer. Completed journals are retained until publication replaces them; requested transaction discovery and service routing remain open.

Tests use real process exit at OWNER arm, directory sync, lock sync and OWNER completion, recreate the repository/OWNER and complete a real publication/native registration flow. They also cover original inode preservation on retry, changed UUID refusal, foreign directory/symlink admission, private root policy, unknown/active activity, immutable artifact refusal, unsafe UUIDs, failed initial/completion OWNER persistence, busy readers, missing completed setup paths and damaged locks. A RED test caught a lock effect after activity changed between directory and lock creation; the initializer now rechecks activity/provenance before that effect. The initial creation and initial-path adoption tests were observed RED before implementation.

The host suite passes 105/105 and the SDK v0.43 publication archive compiles without warnings. This is host recovery evidence and cross compilation, not final PS5 application linkage or console acceptance. Installer/UI integration, startup operation identity/routing, explicit uncertain-registration recovery, final review and the full Wine/gameplay gates remain unfinished. The PS5 remains released and its installed application/runtime are unchanged.
