# Completed operation retirement

The coordinator can advance to a different frozen operation only when its retained previous receipt, metadata and revision exactly identify the active operation's committed result. It holds the stable publisher lease, requires a read-only retirement authorization callback, verifies the old complete set through shared native semantics, rechecks durable Ready/registration authorization and stopped activity, then archives the old journal before blocking the next OWNER operation. Missing callbacks or unrelated/uncompleted operations remain refused.

`SettingsPublicationOwner` requires exact immutable OWNER identities, durable Ready revision with no active journal/failure, immutable package/bottle/artifact ownership, stopped activity and coherent existing native registration. The old Ready state is preserved if advancement fails before the new Block. A failed Ready write or outstanding registration can never be silently retired.

`ArchiveSettingsPublicationOperation` moves the exact active private journal to `settings-operation-<UUID>.v1` without replacing any archive destination. It syncs the parent and verifies exact archived bytes/private policy and active-name absence. Backups are preserved. If a process exits after rename, retry admits only the exact existing archived operation and re-establishes durability; missing/corrupt/foreign archives do not authorize this storage primitive. The primitive's caller supplies prior committed/Ready/lease authorization; storage-only unit tests do not establish that authorization.

A coordinator checkpoint after durable archival supports fresh retry while the previous committed receipt and Ready state remain intact. If a different completed journal is absent, a legitimate fresh update still relies on approved OWNER identity and verified prior receipt/metadata in read-only preflight; historical archives are retained evidence, not an alternative readiness authority. No archive or backup garbage collection is introduced.

Real durable OWNER tests now perform their next-operation update without manually deleting the old journal. They refuse retirement with missing registration or unfinished Ready persistence, stop after archive creation, preserve old Ready state, then complete the next operation/revision without re-registering or repeating committed file effects. Storage tests preserve foreign archives and reject altered permissions/corruption, including actual child process exit immediately after rename before parent sync. The existing effect-only/direct writer fixtures still use explicit test setup for isolated boundaries; they are not production retirement flows.
