# Complete installer inspection and publication handoff

FilesystemPackageInstaller now reports profile publication only after the pinned Wine wrapper's complete committed admission succeeds. It validates the descriptor against the reserved install, supplies the captured EUID and qualified nonblocking shared-lock callback, and retains the reader lease through independent current-kit receipt binding. Missing/pending/corrupt receipts, schema-1 metadata, wrong kit, catalog/profile/input drift, registry semantic mismatch, unexpected or changed DXVK, unsafe file policy and busy publisher refuse publication. Metadata is read by the shared bounded 32768-byte parser; the old 4096-byte schema-1 inspector is removed. Unrelated legitimate Wine registry entries remain accepted. This is publication inspection, not standalone OWNER readiness or guard capability admission.

PublishProfile now validates immutable prerequisites and provider identity, then delegates to the complete OWNER callback with record/paths/publication. It does not create profiles/input directories, generate completion metadata, replace files or perform profile-only retry shortcuts. Complete callback results receive independent committed admission afterward. Immutable staging/inspection no longer requires a publication callback; unavailable publication adapters refuse at publication. The obsolete cross-directory “atomic” callback claim and legacy sync/marker/revision routines are removed.

The native verifier/scalar SHA archive moved from the Hui-specific CMake file to the pinned prospero integration so every launcher presentation uses the same inspector. No Wine build or production capability trust is enabled. Test fixtures now use real pinned SHA for immutable file inventory and schema-2 completion metadata. Test-only direct completion writers are explicitly separate from real coordinator recovery evidence.

RuntimeInstallService also detects a newer OWNER snapshot after package actions rather than overwriting it with the older copied journal. Complete published Ready may return directly; unfinished managed arms and other changed transitions are preserved. Exact immutable identity comparison is shared with SettingsPublicationOwner, including ordered artifact identities/hashes, original launch parameters and recipe/runtime/data/title identity; transition fields remain separately checked.

Host tests cover missing committed receipts (observed RED), package callbacks changing OWNER state (observed RED), and a replay of the old directory-creation regression that fails when a driver fails before pending, then passes after restoration. Both descriptor-relative and native absolute-path policies check pending/corrupt receipts, schema-1 metadata, independently wrong kit binding, registry/DXVK/catalog drift, lock permissions/contention, hardlinks, unrelated registry rewrites and a 64-input metadata set exceeding 4096 bytes. A real filesystem installer test reserves OWNER, stages actual fixture title/bottle files, passes through RuntimeInstallService and SettingsPublicationOwner, interrupts at pending, reloads the durable repository and completes via Resume with one registration and no repeated staging/publication or save changes. Only native inventory/registration is controlled; this remains host evidence.

All 105 Hui host tests and 2/2 installer tests in the independent non-Hui core configuration pass. Actual SDK v0.43 package/publication archives compile; no final native application link or console acceptance is claimed. The host full build emits the existing nonfatal duplicate steam_protocol archive linker warning. App driver/kit/UI wiring, startup jobs before frozen capture or while a prepared update still has Ready OWNER, orphan intent and explicit uncertain-registration recovery, final independent review and Wine/gameplay acceptance remain unfinished. The PS5 is released, and its installed app/runtime were not changed.
